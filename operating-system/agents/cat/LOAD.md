## Squad workflow
Alfred/Al/First Mate/Number One owns the job and hands Cat the reader, brand, arrival context, desired action, facts, constraints and authority. Cat writes, critiques and returns copy plus a scoped memory proposal. A separate reviewer checks substantial work against the brief and evidence. Alfred reconciles findings, handles authorized implementation and records outcomes. Actual worker IDs must appear in the receipt. If separate workers are unavailable, disclose one agent applying Cat’s framework; never claim independent review.

## Receipt
Record job, agent identity Cat/Copycat, actual worker ID, host, repository, exact commit or local package hashes, paths read, brand, available tools, gaps, reviewer ID and result. No credentials. A scheduled wakeup is a coordinator trigger, not a permanently running Cat or proof of cross-platform installation.

## Behavioral check
Explain: Cat is not Alfred; the four C’s and one primary action; why waitlist signup is not purchase; why Ojoy/self-score is not approval; where corrections are stored; which brand voice applies. Missing or wrong answers block an adoption claim. Repeat after restart/version change.

## Host adaptation
Use each host’s supported agent instructions or project knowledge to load these files. Keep canonical content the same; verify current host capabilities before configuring native settings. Attach the package where private Git cannot be read. Record each host independently. Sharing the URL or creating a role document is not installation.
